# Tests and coverage

`cargo test --workspace` needs no game data. Everything is built from generated bytes, so it runs
in CI as well as locally (`RL_DATA=<INSTALHD>` additionally enables `rl-assets/tests/real_data.rs`,
which decodes every real asset).

Current coverage: **about 94% of lines** (`cargo llvm-cov --workspace`). CI fails below 85%.

| Layer | How it is tested |
|---|---|
| `rl-assets` (LZS, CMP, PIE, ETA, INI) | Hand-built files: valid cases, every error path, boundary cases |
| `rl-tool` | A synthetic Mode 2 ISO 9660 image (files, nested and skipped dirs, multi-sector files, CD audio via a CUE), PNG output, the command line |
| `rl-emu` PE loader, VFS, mixer, overlay, video (Cinepak + MS ADPCM), UPnP | Direct calls with generated input; UPnP against a fake router on loopback |
| `rl-emu` Win32 and COM (DirectDraw, DirectSound, DirectPlay) | A bare Unicorn guest (`machine::testing`): the tests call the host import/method and check guest memory |
| `rl-emu` machine, callbacks, exit codes | A generated PE32 whose x86 code calls real imports (`pe::testing::exe`); `tests/cli.rs` runs the real binary against one |
| Debug console | Same bare guest; commands that call game functions get small `mov/ret` stand-ins that record their register arguments |
| `rl-emu` window front-end | SDL's `dummy` video and audio drivers, events pushed into SDL's queue |
| Multiplayer | Loopback TCP and UDP discovery; `net::NET_TEST_LOCK` serialises tests that share the port |
| `rl-game` | Generated sprite sheets and maps; `tests/cli.rs` runs `--shot` |

## What is not covered, and why

* The AI/combat logic of the original game. It lives in `RISING.EXE`, not in this code. It is
  checked by running the real game (`--mission N`, `RL_SCRIPT`, see `docs/DEBUG.md`).
* `upnp::map_port` (needs a real router), `rl-game`'s interactive window loop,
  and the `RL_TRACE` / `RL_WATCH` / `RL_DUMP` debugging hooks in `machine.rs`.

## Running

```
cargo test --workspace
cargo install cargo-llvm-cov && rustup component add llvm-tools-preview
cargo llvm-cov --workspace --summary-only          # table
cargo llvm-cov --workspace --html --open           # line-by-line report
```

Tips for new tests: a test that overwrites code the guest already ran should use a fresh guest
(Unicorn keeps translated copies); `RL_*` environment variables are process-wide, so set them in
tests that run alone or behind a lock.
